# UI 명세 — 출처 추적
현재 HTML/CSS/JavaScript UI를 보존한다. 이미지 시안은 배치 참고이며 예전 사실 판정 문구는 적용하지 않는다.

## 상세 패널 공통
상단 브랜드/설정/다시 분석, 기사 제목·언론사·기자, 시연 배너, 한 줄 요약·분석 상태, 6개 카드, 제목·본문 표현 차이/안내 순서.
좁은 폭의 단일 컬럼이며 기본은 요약 표시이다. 각 카드 우측에 독립 button을 둔다.
button은 aria-expanded와 aria-controls, 네이티브 Enter/Space, 포커스 표시를 가진다.
클릭 시 같은 카드 내부만 펼쳐지고 문구가 자세히 보기 › / 접기 ∧로 바뀐다.
다른 카드를 자동으로 접지 않는다. 동일 article_id 갱신에서는 펼침을 보존하고 기사 ID 변경 시 초기화한다.
분석 중과 오류 시 이전 기사 내용/제목을 숨기며 사용자 재시도를 제공한다.
loading 전용 응답은 없으며 요청 중 클라이언트가 표시한다. 서버 결과는 partial/complete다.

| 카드 ID | 제목 | 기본 | 상세 |
|---|---|---|---|
| context | 배경 및 맥락 | 기사 타임라인 최대 3개 | 기사 내부 전체 흐름·명시된 내용 안내 |
| metadata | 기사 기본 정보 | 언론사·기자·작성일·사건일·장소 | 수정일·원문·공개 프로필 입력값 또는 미확인 |
| claims | 기사의 주장 | 주요 주장 최대 2개 | 원문·발언자·유형·본문에서 보기 |
| evidence | 내용의 근거 | 기사 근거 최대 2개·출처 표기·원본 상태·짧은 설명 | 전체 근거·기사 인용/외부 발견 구분·기관/날짜/URL/종류·9개 관찰·미확인·이유 |

해당 데이터가 없으면 확인된 정보 없음/미확인/관련 기사 없음을 표시한다.
유명 언론사·원본 자료·주의사항 부재를 사실 확인 배지로 바꾸지 않는다.

## Hover
네이버 기사 제목 링크에서 500ms 대기 후 본문 수집·분석.
팝업은 화면 가장자리에 맞춰 배치하고 내부 스크롤한다. 이탈/닫기/Escape 시 늦은 결과를 버린다.
요약, 주요 근거, 출처, 제목·본문 표현 차이, 한 줄 주의사항을 제공한다.
본문 확보 실패·서버 오류를 명확히 표시한다. 기사 링크 클릭을 막지 않는다.
키보드 focus 기반 Hover 대체 탐색·정교한 pointer 전환·실제 목록 성능 개선은 P1/P2다.

## 문장 선택
본문에 존재하는 2~3,000자 선택 후 문장 유형·출처 확인 버튼을 표시한다.
사용자 클릭 전에는 선택 문장 분석을 호출하지 않는다.
전체 추출 본문·선택 텍스트·앞뒤 최대 250자 문맥을 전달한다.
선택 유형, 관련 출처, 원출처 상태, 주의 이유를 보여주고 원문을 자동 판정 색상으로 칠하지 않는다.
기본 드래그·복사를 유지하며 팝업 내부 선택을 재분석하지 않는다.

## 색상·안전·시연
중립 배지는 출처 상태, 주황색은 주의사항 표시용이다. 사실/거짓 의미의 하늘색·빨간색 자동 강조는 없다.
기사·AI 텍스트는 escape하고 URL은 HTTP(S)만 링크로 제공한다.
is_demo=true는 모든 결과 화면에 시연용 예시를 표시하고 가상 링크는 비활성이다.
현재 Chrome headless와 합성 DOM 검사는 통과했으나 설치된 MV3 환경·실제 네이버·화면낭독기 검사는 별도 필요하다.
