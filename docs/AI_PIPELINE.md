# AI 출처 분석 파이프라인
이 서비스는 기사의 진실·거짓, 주장-근거 논리 타당성이나 일치/반박을 판정하지 않으며 점수·확률을 생성하지 않는다.

## 1. 기사와 메타데이터 수집
확장이 제목·본문·언론사·기자·게시/수정일·URL을 추출한다. 본문은 기존 추출기의 12,000자 제한이 있다.
JSON-LD Event의 날짜·장소가 실제 본문에 있는 경우와 Gemini EventInfo의 인용에 포함된 날짜·장소를 연결한다. 없는 값은 null이다. 기자 프로필 독립 수집은 아직 없다. 기사 내부 링크·인용·본문 잘림은 ArticleContext에 담는다.
본문이 없으면 실패한다. 제목만으로 본문 요약을 만들지 않는다.

## 2. 핵심 주장 및 기사 내부 근거
Gemini에 제목·본문(선택 시 focus)을 비신뢰 DATA로 제공한다.
Extraction 스키마로 요약·최대 3개 claims·evidence_mentions·기사 내부 timeline·제목 표현 차이를 받는다.
요약은 짧은 1~2문장을 줄바꿈한 문자열로 요청한다. UI에서 글머리표를 붙이며 기존 문단 응답도 처리한다. 타임라인은 기사에 명시된 사건 최대 4개만 추출하고 날짜 미확인은 그대로 남긴다. 네모·화살표는 표시 형식이며 새로운 인과관계를 생성하지 않는다.
사실 서술/인용/의견/해석/예측 등의 유형은 진위 상태가 아니다.
서버는 original_text/article_quote가 실제 본문에 포함되는지 확인하고 speaker·자료명·출처 표기를 검사한다.
claim_text는 원문으로 다시 설정하여 '검토'를 '확정'으로 바꾸는 재서술을 방지한다.
인용 포함 검사만으로 의미·발언 귀속이 정확하다고 보증하지는 않으므로 실제 표본 평가가 필요하다.

## 3. 근거의 원출처 검색
기사 근거의 source_label/document_title/article_quote에서 최대 3개 검색어를 만든다.
Tavily 일반 검색으로 질의별 최대 5건 및 raw_content를 요청한다.
URL 정규화와 동일 URL 중복 제거 후 서버가 해시 기반 source ID를 부여한다.
제목/URL/published_date/retrieved_at과 원문 앞 16,000자를 보존해 다음 단계에 제공한다.
검색 요약은 탐색 힌트이며 raw_content가 없으면 이를 원문 관찰로 대체하지 않는다.
실제 검색 실패·완료된 빈 결과·근거 언급 자체 없음은 각각 failed/completed/not_run으로 구분한다. raw_content가 없는 검색 URL 최대 3개는 Tavily extract로 보강한다. 반환 URL을 원래 후보 허용 목록과 대조하며 새 URL은 저장하지 않는다. 보강 실패는 검색 미발견과 구분하여 content_status/pipeline_errors에 기록한다.

## 4. 출처의 정체·원본 관계·전문성·검증 가능성
Gemini는 주어진 source ID에 한해서만 자료 연결과 SourceFacts의 정확한 원문 인용을 추출한다.
SourceFacts: identity, authorship, originality, expertise, information_access, date_context,
public_access, methodology, interests, independence. 없는 속성은 null이다.
서버가 실제 raw_content에 포함되지 않는 excerpt를 제거한다.
article_cited는 기사 자료명 또는 엄격한 기관·인용 연결이 확인되는 경우이고, 그 외는 external_found로 둔다.
같은 기관의 다른 자료나 주제 유사성만으로 기사 인용 자료라고 표시하지 않는다.
original_found는 자료 연결·원자료 인용·기관 정체를 함께 요구한다.
이 과정도 '최초 원본'의 완전한 증명은 아니며 원자료 관계를 사람이 검토해야 한다.
원문에 적힌 자기소개는 실제 전문자격/이해관계 부재에 대한 독립 증명으로 취급하지 않는다.

## 5. 출처 공신력 관련 관찰
임의 등급이나 유명세 기반 평가 대신 확인된 인용과 unknown_fields를 함께 제시한다.
기관·원자료·전문분야·접근 경로·시점·공개 범위·조사방법·이해관계·독립성 중 무엇이 관찰됐는지 설명한다.
공개 원문이 있다는 것, 기관이 공신력 있다는 것, 원본을 찾았다는 것을 주장 입증으로 바꾸지 않는다.

## 6. 객관적인 주의사항
일반 코드가 원출처 미발견/재인용/미명시/익명/조사방법 미확인/이해관계 관련 문구/날짜 차이/의견·예측을 안내한다.
자료가 기사보다 365일을 초과하여 오래되면 날짜 차이와 최신 자료 확인 필요성만 적는다.
양쪽 날짜나 속성이 없으면 미확인을 유지한다.
caution / none_identified / unknown과 비어 있지 않은 reasons를 저장한다. details에는 이유별 source_ids/claim_ids를 연결한다. 인용 위치는 서버가 article_span으로 산출한다.
none_identified는 현재 관찰 범위에서 별도 주의사항이 없다는 뜻이며 진위의 결론이 아니다.
검색할 기사 근거를 확보하지 못해 검색 자체를 실행하지 않은 not_run은 검색 실패와 다른 이유로 설명한다. 검색 완료 후 자료 연결 정보가 부족한 경우도 실패라고 표현하지 않는다.

## 7. 결과 저장과 전달
Pydantic 모델에 없는 필드와 알 수 없는 참조를 거부한다. 출처 URL은 검색에서 온 값만 사용한다.
완료/부분 분석 결과의 공통 ArticleAnalysis를 캐시하고 preview·selection 응답으로 필요한 필드만 전달한다.
UI는 source_status·caution을 표시하며 사실/거짓 자동 색상 강조는 하지 않는다.
독립성이나 관련 기사 전문 비교를 확인하지 못했으면 그렇게 명시한다.

## 다른 보도 내용 비교
관련 기사는 서로 다른 발행자 최대 5건을 목록으로 저장한다. 앞 3건의 raw_content(앞 8,000자), 없으면 content(앞 2,000자), 그것도 없으면 제목(앞 500자)을 비교 자료로 사용한다. 나머지는 not_compared로 유지한다. 검색·비교 호출 횟수를 늘리거나 임의 URL을 직접 수집하지 않는다.
Gemini의 추가 구조화 호출 1회로 공통 보도 항목과 표현·강조 차이의 양쪽 인용을 추출한다. 본문 전체의 부재나 취재 의도를 추정하지 않는다.
서버는 report ID와 현재 기사/해당 보도 자료의 정확한 인용을 대조하고, 허구 ID·인용·다른 보도 인용을 제거한다. 각 보도에 최대 6개 항목만 저장한다.
이 비교는 사실 여부나 주장-근거의 지지/반박 판정이 아니다. 보도의 독립성도 비교 결과에서 추정하지 않는다. 비교 범위를 명시하고 실패/불충분 시 기사 목록과 출처 분석을 유지한다.
Mock도 같은 인용 검사를 통과하며 시연 기사와 가상 보도에 공통 주제·강조 차이를 제공한다.

## 평가 계획
단위 테스트는 공급자를 대체하며 정확한 제약·오류·캐시를 확인한다. 실제 모델 성능의 증거가 아니다.
P0에서 실제 기사 2~3건과 원문 자료를 저장 범위에 유의해 수동 대조하고,
추출 누락/의미 변경/잘못된 출처 연결/관찰 인용 오류/과잉·누락 주의사항을 유형별로 기록한다.
실제 기본 연결의 관찰은 VALIDATION.md에 기록한다. 모델 목록·작은 구조화 응답·검색 연결의 성공과 기사 전체 품질·계정별 할당량·응답시간 평가는 구분한다.

## 입력 기반 Mock와 실제 연결의 구분
MockLLM/MockSearch도 동일 Analyzer를 거친다. 기사 원문에서 2~3개 문장을 시연 추출하고, 명시적으로 일치하는 가상 자료만 fixture 검색으로 반환한다. 출처는 원문 인용/ID 검사와 동일 주의사항 규칙을 통과한다. 실제 AI 성능·검색 성공의 증거는 아니며 모든 화면의 is_demo 표시를 유지한다.
새 선택 분석은 부모 article_id와 별도의 analysis_id 및 scoped claim ID를 사용하고 원본 기사 결과를 덮어쓰지 않는다. 기존 주장 재사용 여부는 matched_claim_ids로 표현한다.

## 제목의 의미와 맥락 표현 추가
기존 EXTRACT 호출에서 headline_explanation의 의미·이유와 타임라인 label·is_main_event를 함께 생성한다. 작성자의 내면 의도를 추정하지 않고 본문에서 설명되는 제목의 의미만 1~2문장으로 정리한다. 각 이유는 내용과 한정 의미를 유지한 간결한 표현이며 실제 기사 article_quote를 함께 반환해야 한다. 서버는 인용 존재·발급된 ID를 확인하고 연결된 출처 ID를 채운다.
타임라인은 주요 사건과 기사에 명시된 전후 맥락만 선택한다. 날짜는 인용에 존재하는 값만 쓰고, label은 검토·의혹·예정 등의 한정 표현을 보존한 짧은 명사형이다. 원문을 label로 덮어쓰지 않는다. 선택 문장 전용 분석은 기사 전체 제목 설명을 비워 부모 분석과 구분한다.

## Hover 경량 경로
Hover는 동일 EXTRACT 결과만 받아 반환하고 외부 근거 검색·공식 자료·출처 속성·보도 비교는 실행하지 않는다. 후속 패널이 추출을 재사용해 기존 전체 파이프라인을 이어간다. 제목 이유 text는 한 문장 서술 대신 짧은 표현으로 생성하며 article_quote는 원문을 그대로 보존한다.

## 표시 상태와 AI 역할 (2026-11-14)
Gemini에 매체 신뢰도나 점수/색상을 고르게 하지 않는다. 기존 추출과 출처 분석을 유지하며 클라이언트가 근거 연결·원문 확보·주의 이유·단계별 오류로 출처 확인·주의 상태를 표시한다. LLM의 자유문 제목 설명과 보도 공통/차이 개수를 신뢰 등급으로 환산하지 않는다. 구체적 제목 경고를 상단 상태에 추가하는 것은 인용과 연결을 검증할 구조화 근거가 마련된 뒤 진행한다.

## 선택 단어 설명 (2026-11-14)
사용자 버튼 클릭 때만 실행한다. 선택 단어와 실제 문맥을 검증하고, Tavily의 사전 도메인 검색 결과를 서버에서 ID 부여한다. Gemini는 일반 의미·문맥 해석과 후보 사전의 실제 뜻풀이를 정리한다. 서버가 후보 ID·사전 인용의 원문 포함·표제어 연관·문맥 인용을 검사한다. 사전 뜻풀이를 확인하지 못하면 사전 정의처럼 표시하지 않는다. 원문과 검색 요약을 구분한다. 주장의 진위/신뢰도를 판정하지 않는다.

## 보도 간 재확인 후보 (2026-11-14)
기존 COMPARE_REPORTS 호출에서 같은 대상·사건·시점·단위를 전제로 양립하기 어려운 서술/수치와 인용 조건 차이를 후보로 추출한다. 단순한 강조점·다른 시간/집계 범위는 제외하도록 지시한다. 서버가 보도 ID·양쪽 인용·공통 표현·인용 출처 URL 관계를 대조한다. AI 후보는 의미 검증 완료가 아니며 표시에도 충돌 가능성/왜곡 여부 확인 필요를 명시한다. 전문 전체를 확보했다거나 어느 쪽이 옳다고 주장하지 않는다. LLM/API 호출 수는 유지한다.

## 원격 main의 외신 기능 통합 (2026-11-14)
기준 원격 main은 cd1794e(PR #8 외국기사 번역, PR #9 외신 검색/원문 대조/관련 기사 필터/작성일 추출)다. 내 기능의 보관 커밋은 bedc691이며 feat/source-caution-update에서 병합한다.
외신/기관 도메인 검색, 영어 검색어·후속 보도 검색, 관련 기사 필터·정렬과 작성일 추출을 보존했다. 주장/근거의 한국어 번역과 비교 구절의 번역/차이 설명은 원문과 분리한다.
사용자 선택에 따라 상단 ‘원문과 다른 점’ 카드를 유지하고 빨간 재확인 안내와 관련 기사 이동을 연결한다. 기존 6개 카드의 독립 토글·고정 선택·단어 API는 유지한다.
공식 매체 도메인과 추정 번역의 단어 유사성은 원문 후보 선정에만 사용한다. 실제 인용 관계/원본 확인으로 자동 승격하지 않는다. 원문 후보는 상단 카드에서 ‘인용 관계 미확인’으로 구분하고 두 인용·AI 번역·차이 설명을 제공한다. 직접 링크 등 실제 연결 근거와 원자료 관찰이 확인될 때만 기존 출처 확인 로직을 적용한다.
신뢰 지수·가중치(귀속 차이 3배 포함)는 사용하지 않는다. 서술 충돌의 빨강/요약 수준의 노랑은 기존 재확인 조건을 따른다. 원문 후보라는 이유만으로 빨강이 되거나 실제 인용 원본이 되지 않는다.
두 브랜치가 각각 1.8을 사용했으므로 통합 후 data_version/health/캐시는 source-tracing-v1.9다. 서버 재시작 → npm run build → 확장 새로고침 → 기사 F5 → 다시 분석으로 적용한다.
