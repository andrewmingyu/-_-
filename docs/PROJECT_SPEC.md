# 뉴스체크 AI — 출처 추적 요구사항 명세서
기준: 2026-11-11. 최신 사용자 지시를 반영한 source-tracing-v1 계약.
이 문서가 이전 팩트체크 설계와 충돌하면 이 문서를 우선한다.

## 1. 목적과 금지 사항
기사에서 제시한 근거와 원출처를 추적하고, 공신력·공개성·검증 가능성의 확인 정보와 미확인 정보를 보여준다.
AI는 기사·주장의 진위, 논리적 타당성, 주장과 근거의 일치/반박을 판정하지 않는다.
기관의 유명세, 보도 수, 출처 확인 또는 주의사항 부재를 진실성 입증으로 사용하지 않는다.
신뢰도 점수·확률과 사실/거짓 자동 색상 강조를 만들지 않는다.
문장 유형은 사실 여부와 독립적이다. 인용·검토·예정·가능성 등의 원문 표현을 보존한다.
기자 약력·자료·URL·발행일·독립성·이해관계 부재를 추정하지 않는다.

## 2. 현재 구현 및 보존
현재 실행 폴더는 `newscheck 4/`이며 HTML/CSS/JavaScript MV3 확장이다.
불필요한 React 재작성 없이 기존 추출·원문 위치 이동·설정·아이콘을 보존한다.
`shared/types.ts`에 TypeScript 계약, `backend/app/models.py`에 Pydantic 모델을 둔다.
Gemini·Tavily는 서버에서만 호출한다. 기존 브라우저 키는 읽거나 전송하지 않으며 설정에서 사용자가 삭제할 수 있다.

## 3. 원출처 및 주의사항 계약
근거 언급 `evidence_mentions`는 기사에 제시된 자료·발언이다. 정확한 기사 인용과 연결할 주장 ID를 저장한다.
`sources`는 실제 검색 반환 URL을 서버가 정규화·ID 부여한 자료만 포함한다.
`discovery=article_cited`: 기사에서 명시한 자료/기관과의 연결을 확인한 출처.
`discovery=external_found`: 검색에서 추가 발견했으나 기사 인용 자료와 연결되지 않은 출처.
이 구분은 기사의 실제 링크 존재 여부나 주장의 입증 여부가 아니다.

원출처 상태 `source_status` / `original_status`:
- `original_found`: 원문 및 최초 작성/발표 관계를 확인.
- `secondary_only`: 재인용 자료만 확인.
- `source_not_found`: 검색이 완료되었으나 관련 원출처를 찾지 못함.
- `unknown`: 정보 부족·검색 실패 등으로 원출처 상태를 결정하기 어려움.

주의사항 `caution`은 `{status, reasons[]}`이며 reasons는 한 개 이상 필수:
- `caution`: 객관적 주의사항이 확인됨.
- `none_identified`: 확보한 출처 정보에서 별도 주의사항을 찾지 못함. 참이라는 뜻이 아님.
- `unknown`: 출처 분석이 불충분함.
주의사항이 있으면 그 이유를 먼저 제시하고, 동시에 확인하지 못한 항목도 보존한다.

## 4. AI 및 일반 코드의 역할
1. Gemini: 요약, 원문에 있는 주요 주장 1~3개, 발언자, 근거 언급, 자료 종류, 문장 유형 추출.
2. 서버: 원문에 없는 인용문과 발언자·자료명 제거. claim_text에 원문 표현 보존.
3. Tavily: 기사에 명시된 자료·기관을 검색하고 실제 결과 URL과 원문 내용 확보.
4. Gemini: 제공한 검색 ID에 대해서만 원출처 연결과 출처 속성의 정확한 문구 추출.
5. 서버: 출처 ID 허용 목록 및 인용문 원문 포함 여부 확인. 검색 요약만으로 원본을 확정하지 않음.
6. 서버: 관찰된 속성에서 주의사항과 미확인 항목을 결정. 진위·타당성 대조 단계 없음.
7. 저장: 정규화 URL + 본문 SHA-256 + 모델/스키마 버전·메타데이터로 캐시 및 동시 요청 중복 방지.
   Hover·패널·선택 문장에서 기존 주장에 대응하면 같은 분석을 재사용한다.
   기존 주장에 없는 선택 문장은 별도로 출처를 추적하고 기사 전체 결과를 덮어쓰지 않는다.

출처 속성: 정체/작성기관, 원자료·재인용, 전문성, 정보 접근 경로, 작성 시점,
공개 범위, 조사 방법, 이해관계, 자료 독립성.
각 속성은 원문 excerpt 또는 null이다. null은 '없다'가 아니라 '확인하지 못했다'이다.
원자료 판별은 기사 자료명/기관 연결 및 원문상의 작성·발표 관계를 함께 확인해야 한다.
모델이 만든 새로운 URL·출처 ID는 저장하지 않는다. 독립 자료의 개수를 임의로 계산하지 않는다.

## 5. 주의사항 규칙
- 근거/출처 미명시, 익명 발언, 검색 완료 후 원출처 미발견, 재인용만 확인.
- 연구·통계 자료인데 조사 방법 미확인.
- 자료 작성자의 이해관계에 관한 문구가 있는 경우 그 문구를 그대로 제시.
- 기사 작성일보다 자료 발행일이 365일을 초과하여 앞서면 날짜 차이와 최신 자료 확인 필요성을 안내.
  이는 최신성 확인을 위한 표시 기준이며 자료가 틀리거나 무효라는 판정이 아니다.
- 의견·해석·예측을 발생한 사건과 구분하도록 안내.
- 검색 실패 또는 속성 부족은 unknown으로 보존. 검색 오류를 출처 미발견으로 바꾸지 않는다.
- none_identified는 원본 및 출처 속성이 확보되고 적용 규칙상 주의사항이 없을 때만 사용한다.

## 6. 상세 패널 — 6개 독립 카드
기본은 좁은 폭의 세로 카드. 각 카드 우측에 자세히 보기 / 접기 버튼.
여러 카드를 동시에 펼칠 수 있고 비동기 갱신 후에도 상태를 유지한다.
전역 하단 더보기 버튼 금지. 네이티브 button, aria-expanded, aria-controls, 포커스 표시 필수.

1. 배경 및 맥락: 기사에 명시된 이전 상황·시간순 사건. 원문 밖 배경 생성 금지.
2. 기사 기본 정보: 언론사·기자·작성일·수정일·사건일·장소·확인 가능한 기자 링크. 미확인은 그대로 표시.
3. 기사의 주장: 요약/주장. 상세는 원문·발언자·사실 서술/인용/의견/해석/예측 유형.
4. 내용의 근거: 기사 근거, 원출처, 원본 확인 상태, 출처 설명.
   상세는 기관·날짜·URL·종류·원자료 여부·속성별 원문·미확인 항목·분석 이유.
5. 주의할 것: 출처 불명확, 검증 가능성 부족, 해석/예측, 현재 미확인, 추가 확인 자료를 분리.
6. 비슷한 주제의 기사: 다른 언론사·시점·주요 내용. 동일 발행자 중복 억제.
   원문을 비교하지 않은 검색 요약은 그렇게 표시하고 독립성은 확인 전 미확인으로 둔다.

상단은 한 줄 요약/분석 상태, 하단은 제목·본문 표현 차이와 종합 안내.
모든 사실/거짓 색상은 사용하지 않는다. 주황색은 주의사항에만 사용한다.
시연 데이터는 화면마다 '시연용 예시'로 표시하고 가상 URL은 클릭 링크로 제공하지 않는다.

## 7. Hover 및 선택 문장
Hover 500ms 지연, 이탈/기사 변경 시 늦은 응답 무시, 원래 기사 클릭 유지.
클릭 전 본문을 실제 확보한 경우에만 요약. 초기 지원은 네이버 기사 링크.
Hover: 요약, 주요 근거, 출처, 제목·본문 표현 차이, 한 줄 주의사항.
선택 문장: 사용자 클릭 후 본문/선택/주변 문맥을 전송하고 유형·출처·원출처 상태·주의 이유 표시.
원문을 사실/거짓 색상으로 자동 하이라이트하지 않는다.
서버 오류·본문 미확보·미지원 링크는 명확히 안내하고 사용자의 복사/선택 동작을 유지한다.

## 8. API
- GET /health: 모드 및 스키마 버전.
- POST /api/articles/analyze: AnalyzeRequest → ArticleAnalysis.
- POST /api/preview: 같은 AnalyzeRequest → Preview.
- POST /api/claims/check: SelectionRequest → SelectionAnalysis.
입력은 url, title, page_text, metadata, refresh. 선택은 selected_text, surrounding_text, article_id 추가.
공통 결과는 기사/주장/evidence_mentions/sources/caution/related_articles/search_status/search_errors/analyzed_at.
정확한 필드 및 enum은 models.py, shared/types.ts 및 docs/api.schema.json 참조.
모델 extra=forbid, 알 수 없는 참조 ID 거부, 오류 응답에 키/공급자 원문 오류 노출 금지.
백엔드는 임의 URL을 직접 fetch하지 않는다. Hover fetch는 확장 서비스 워커에서 네이버 HTTPS 기사로 제한.
소스 HTML/본문은 실행하지 않고 렌더 시 escape 및 HTTP(S) 링크만 허용한다.

## 11. 기능별 요구사항

### F01 뉴스 제목 Hover 감지
- 목적: 기사 클릭 전 빠른 탐색
- 입력: 네이버 기사 링크·mouseover/out
- 동작·출력: 500ms 대기 후 수집 요청, 이탈 시 취소
- 예외·제약: 미지원 URL 무시·늦은 응답 폐기
- 완료 기준: 실제 목록에서 의도한 링크만 감지하고 클릭을 방해하지 않음
- 현재 상태·근거: 추가 검증 필요; newscheck 4/content.js; scripts/browser-smoke.mjs

### F02 Hover 요약 팝업
- 목적: 읽을 기사 빠르게 파악
- 입력: 확보한 기사 본문·Preview
- 동작·출력: 요약·주요 근거·출처·표현 차이·주의사항 표시
- 예외·제약: 본문 미확보/통신 오류를 안내하고 제목 요약으로 대체하지 않음
- 완료 기준: Chrome 설치 상태에서 본문 기반 결과가 표시됨
