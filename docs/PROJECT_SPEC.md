# 뉴스체크 AI — 출처 추적 요구사항 명세서
기준: 2026-11-12. source-tracing-v1 경로·기본 계약을 유지하고 data_version=source-tracing-v1.8에서 보도 내용 비교를 추가했다.
이 문서가 이전 팩트체크 설계와 충돌하면 이 문서를 우선한다.

## 1. 목적과 금지 사항
기사에서 제시한 근거와 원출처를 추적하고, 공신력·공개성·검증 가능성의 확인 정보와 미확인 정보를 보여준다.
AI는 기사·주장의 진위, 논리적 타당성, 주장과 근거의 일치/반박을 판정하지 않는다.
다른 보도의 공통 주제·서술·수치·시점·인용·강조점 비교는 허용한다. 공통 보도는 사실 확인이 아니며, 다른 표현도 어느 쪽이 옳다는 판단이 아니다.
기관의 유명세, 보도 수, 출처 확인 또는 주의사항 부재를 진실성 입증으로 사용하지 않는다.
신뢰도 점수·확률과 사실/거짓 자동 색상 강조를 만들지 않는다.
문장 유형은 사실 여부와 독립적이다. 인용·검토·예정·가능성 등의 원문 표현을 보존한다.
기자 약력·자료·URL·발행일·독립성·이해관계 부재를 추정하지 않는다.

## 2. 현재 구현 및 보존
현재 실행 폴더는 `newscheck 4/`이며 HTML/CSS/JavaScript MV3 확장이다.
불필요한 React 재작성 없이 기존 추출·원문 위치 이동·설정·아이콘을 보존한다.
`shared/types.ts`에 TypeScript 계약, `backend/app/models.py`에 Pydantic 모델을 둔다.
Gemini·Tavily는 서버에서만 호출한다. 기존 브라우저 키는 읽거나 전송하지 않으며 설정에서 사용자가 삭제할 수 있다.

## 3. 원출처 및 주의사항 계약
근거 언급 `evidence_mentions`는 기사에 제시된 자료·발언이다. 정확한 기사 인용과 연결할 주장 ID를 저장한다.
`sources`는 실제 검색 반환 URL을 서버가 정규화·ID 부여한 자료만 포함한다.
`discovery=article_cited`: 기사에서 명시한 자료/기관과의 연결을 확인한 출처.
`discovery=external_found`: 검색에서 추가 발견했으나 기사 인용 자료와 연결되지 않은 출처.
이 구분은 기사의 실제 링크 존재 여부나 주장의 입증 여부가 아니다.

원출처 상태 `source_status` / `original_status`:
- `original_found`: 원문 및 최초 작성/발표 관계를 확인.
- `secondary_only`: 재인용 자료만 확인.
- `source_not_found`: 검색이 완료되었으나 관련 원출처를 찾지 못함.
- `unknown`: 정보 부족·검색 실패 등으로 원출처 상태를 결정하기 어려움.

주의사항 `caution`은 `{status, reasons[]}`이며 reasons는 한 개 이상 필수:
- `caution`: 객관적 주의사항이 확인됨.
- `none_identified`: 확보한 출처 정보에서 별도 주의사항을 찾지 못함. 참이라는 뜻이 아님.
- `unknown`: 출처 분석이 불충분함.
주의사항이 있으면 그 이유를 먼저 제시하고, 동시에 확인하지 못한 항목도 보존한다.

## 4. AI 및 일반 코드의 역할
1. Gemini: 요약, 원문에 있는 주요 주장 1~3개, 발언자, 근거 언급, 자료 종류, 문장 유형 추출.
2. 서버: 원문에 없는 인용문과 발언자·자료명 제거. claim_text에 원문 표현 보존.
3. Tavily: 기사에 명시된 자료·기관을 검색하고 실제 결과 URL과 원문 내용 확보.
4. Gemini: 제공한 검색 ID에 대해서만 원출처 연결과 출처 속성의 정확한 문구 추출.
5. 서버: 출처 ID 허용 목록 및 인용문 원문 포함 여부 확인. 검색 요약만으로 원본을 확정하지 않음.
6. 서버: 관찰된 속성에서 주의사항과 미확인 항목을 결정. 진위·타당성 대조 단계 없음.
7. 저장: 정규화 URL + 본문 SHA-256 + 모델/스키마 버전·메타데이터로 캐시 및 동시 요청 중복 방지.
   Hover·패널·선택 문장에서 기존 주장에 대응하면 같은 분석을 재사용한다.
   기존 주장에 없는 선택 문장은 별도로 출처를 추적하고 기사 전체 결과를 덮어쓰지 않는다.

출처 속성: 정체/작성기관, 원자료·재인용, 전문성, 정보 접근 경로, 작성 시점,
공개 범위, 조사 방법, 이해관계, 자료 독립성.
작성자(authorship)를 포함한 10개 속성을 처리한다. 각 속성은 원문 excerpt 또는 null이다. null은 '없다'가 아니라 '확인하지 못했다'이다.
원자료 판별은 기사 자료명/기관 연결 및 원문상의 작성·발표 관계를 함께 확인해야 한다.
모델이 만든 새로운 URL·출처 ID는 저장하지 않는다. 독립 자료의 개수를 임의로 계산하지 않는다.

## 5. 주의사항 규칙
- 근거/출처 미명시, 익명 발언, 검색 완료 후 원출처 미발견, 재인용만 확인.
- 연구·통계 자료인데 조사 방법 미확인.
- 자료 작성자의 이해관계에 관한 문구가 있는 경우 그 문구를 그대로 제시.
- 기사 작성일보다 자료 발행일이 365일을 초과하여 앞서면 날짜 차이와 최신 자료 확인 필요성을 안내.
  이는 최신성 확인을 위한 표시 기준이며 자료가 틀리거나 무효라는 판정이 아니다.
- 의견·해석·예측을 발생한 사건과 구분하도록 안내.
- 검색 실패 또는 속성 부족은 unknown으로 보존. 검색 오류를 출처 미발견으로 바꾸지 않는다.
- none_identified는 원본 및 출처 속성이 확보되고 적용 규칙상 주의사항이 없을 때만 사용한다.

## 6. 상세 패널 — 6개 독립 카드
기본은 좁은 폭의 세로 카드. 각 카드 우측에 자세히 보기 / 접기 버튼.
상단은 글머리표 요약(1~2문장)과 그보다 좁은 기사 기본 정보를 좌우로 배치한다. 배경은 날짜·짧은 설명의 네모와 화살표로 표시한다. 680px 이상에서는 주장/근거를 2열로, 배경/주의할 것/관련 기사는 전체 폭으로 둔다. 시안의 전역 토글은 적용하지 않는다.
여러 카드를 동시에 펼칠 수 있고 비동기 갱신 후에도 상태를 유지한다.
전역 하단 더보기 버튼 금지. 네이티브 button, aria-expanded, aria-controls, 포커스 표시 필수.

1. 배경 및 맥락: 기사에 명시된 이전 상황·시간순 사건. 원문 밖 배경 생성 금지.
2. 기사 기본 정보: 언론사·기자·작성일·수정일·사건일·장소·확인 가능한 기자 링크. 미확인은 그대로 표시.
3. 기사의 주장: 요약/주장. 상세는 원문·발언자·사실 서술/인용/의견/해석/예측 유형.
4. 내용의 근거: 기사 근거, 원출처, 원본 확인 상태, 출처 설명.
   상세는 기관·날짜·URL·종류·원자료 여부·속성별 원문·미확인 항목·분석 이유.
5. 주의할 것: 출처 불명확, 검증 가능성 부족, 해석/예측, 현재 미확인, 추가 확인 자료를 분리.
6. 비슷한 주제의 기사: 다른 언론사·시점·주요 내용. 동일 발행자 중복 억제.
   기본 화면은 최대 5건의 제목·언론사·작성일을 기사별 한 줄로 표시한다. 독립적인 자세히 보기와 기사별 펼침에서 앞 3건까지 현재 기사와 비교 보도의 인용 구절을 나란히 표시한다.
   본문 발췌/검색 요약/제목만의 비교를 구분하고 독립성은 확인 전 미확인으로 둔다. 한쪽 전문에서 정보가 없거나 생략됐다고 추정하지 않는다.

상단은 한 줄 요약/분석 상태, 하단은 제목·본문 표현 차이와 종합 안내.
모든 사실/거짓 색상은 사용하지 않는다. 주황색은 주의사항에만 사용한다.
시연 데이터는 화면마다 '시연용 예시'로 표시하고 가상 URL은 클릭 링크로 제공하지 않는다.

## 7. Hover 및 선택 문장
Hover 250ms 지연, 이탈/기사 변경 시 늦은 응답 무시, 원래 기사 클릭 유지.
클릭 전 본문을 실제 확보한 경우에만 요약. 지원은 네이버 뉴스·연합뉴스TV 기사 링크이며 일반 페이지·다른 도메인·자격증명이 있는 URL은 수집하지 않는다.
Hover: 핵심 요약과 제목·본문 표현 차이. 주장·근거·출처·주의사항 상세는 패널에서 확인한다.
선택 문장: 사용자 클릭 후 본문/선택/주변 문맥을 전송하고 유형·출처·원출처 상태·주의 이유 표시.
원문을 사실/거짓 색상으로 자동 하이라이트하지 않는다.
서버 오류·본문 미확보·미지원 링크는 명확히 안내하고 사용자의 복사/선택 동작을 유지한다.

## 8. API
- GET /health: 모드 및 스키마·데이터 버전.
- GET /api/articles/{article_id}?url=...: 만료 전 기존 결과 조회; 없거나 다른 URL이면 404.
- POST /api/articles/analyze: AnalyzeRequest → ArticleAnalysis.
- POST /api/preview: 같은 AnalyzeRequest → Preview.
- POST /api/claims/check: SelectionRequest → SelectionAnalysis.
입력은 url, title, page_text, metadata, refresh. 선택은 selected_text, surrounding_text, article_id 추가.
공통 결과는 기존 필드에 event/article_context/section_states/pipeline_errors/data_version을 기본값 있는 필드로 추가한다.
정확한 필드 및 enum은 models.py, shared/types.ts 및 docs/api.schema.json 참조.
모델 extra=forbid, 알 수 없는 참조 ID 거부, 오류 응답에 키/공급자 원문 오류 노출 금지.
백엔드는 임의 URL을 직접 fetch하지 않는다. Hover fetch는 확장 서비스 워커에서 네이버 뉴스·연합뉴스TV의 허용된 HTTPS 기사 주소로 제한한다.
소스 HTML/본문은 실행하지 않고 렌더 시 escape 및 HTTP(S) 링크만 허용한다.

## 9. 단계와 완료 기준
mock UI → 실제 기사 추출/API → Gemini 구조화 → Tavily 원출처 추적 → 선택 문장 및 Hover 통합.
기존 데이터의 사실판정 필드/점수/색상과 직접 AI 호출은 제거한다.
검색 성공 빈 결과·검색 실패·검색 요약만 존재·잘못된 ID·존재하지 않는 인용문·재인용·익명·이해관계·오래된 날짜를 테스트한다.
6개 카드 동시 열기/접기, 시연 배너, HTML/URL 안전성, 서로 다른 언론사 목록을 테스트한다.
동일 기사 세 화면의 결과 공유, 본문 수정/강제 갱신, 실패 후 재시도도 검사한다.
npm test, npm run typecheck, npm run build 및 pytest를 실행하고 실제 결과를 보고한다.
실제 Chrome 로드와 실제 API 품질은 자동 테스트와 구분하여 수동 검토한다.

## 12. 추가 완료 조건
- 보도 비교는 서버가 검색에서 부여한 report ID와 양쪽 실제 구절을 요구한다. 허구 ID·구절·다른 보도의 인용 전용은 저장하지 않는다.
- 최대 3개 보도, 보도별 6개 항목, 각 인용 8~600자로 제한한다. 비교 불충분/실패 시 목록과 기존 출처 분석은 유지하고 재시도할 수 있게 한다.
- source-tracing-v1.8를 캐시 키에 반영해 비교 기능이 없는 이전 결과와 구분한다. 기존 응답의 비교 필드는 생략 가능하다.
- 기사 내부 링크·인용은 ArticleContext로 전달하고 원문 밖 자료는 기사 인용으로 생성하지 않는다.
- Claim/Mention의 article_span은 정규화 page_text의 Unicode 문자 위치로 서버가 산출한다.
- EventInfo의 시점·장소는 같은 기사 인용에 포함될 때만 사용한다. JSON-LD Event를 본문과 연결하지 못하면 미확인이다. 본문 날짜를 보도일로 대체하지 않는다.
- 새 선택 분석은 별도 analysis_id 및 scoped claim ID를 가지며 부모 기사 article_id는 유지한다.
- 서버 Mock은 실제 Analyzer의 추출→검색→출처 관찰→주의사항→캐시 경로를 시연 공급자로 실행한다. ?demo 정적 UI fixture는 별도로 유지한다.
- Hover는 워커의 30초/64건 입력 인덱스에서 부모 분석을 찾고 서버 GET 조회/본문 해시 검사를 거친다. 없으면 HTML 수집→기존 preview POST로 진행한다.
- 검색 URL 후보에 한해서만 Tavily extract로 원문을 보강한다. 실패/요약만 확보는 content_status와 pipeline_errors로 구분한다.
- 각 카드에 ready/empty/partial/error를 표시하고 클라이언트의 요청 중 상태는 loading으로 표시한다. 서버 단계 스트리밍은 구현하지 않는다.
- 공급자 오류는 configuration_missing/rate_limited/timeout/network_error/invalid_response/provider_error를 구분한다. 원문 확보 누락은 document_unavailable이다.
- 사용자 흐름 A/B/C/D를 실제 worker와 로컬 HTTP mock 서버로 검사하고 기존 독립 테스트를 유지한다.

- 출력: 제목의 의미 아래 1~2문장 설명, 이유 소제목 아래 이유별 간결한 표현의 글머리표. 출처 속성은 기본 목록에서 길게 펼치지 않는다.
- 더보기: 이유의 실제 기사 인용과 근거 이동 버튼. 관련 자료가 있으면 내용의 근거 카드를 펼쳐 해당 항목으로 이동하며 없으면 근거 확인 현황으로 이동한다. 다른 카드의 펼침 상태는 유지한다.
- 맥락: 실제 기사에 존재하는 전후 흐름만 사용하며 날짜는 별도, 설명은 6~16자 안팎(최대 24자)의 짧은 표현으로 표시한다. 주요 사건 하나는 굵은 테두리와 텍스트 표지를 사용한다. 날짜나 배경이 없으면 생성하지 않는다.
- 예외: 원문 이유가 없거나 이전 응답에 필드가 없으면 빈 상태를 표시한다. 긴 원문은 더보기에서 보존하며 네모에서는 말줄임을 사용하지 않는다.
- 검증: 허위 인용/참조 거부, 이전 응답 호환, 근거 이동·독립 토글·320/440/880px·다크모드·Mock 전체 연결 확인.

## 출처 확인·주의 상태 요구사항 (2026-11-14)
- 목적: 점수 대신 확인 가능한 출처 주의 이유와 핵심 조사 진행 상태를 빠르게 전달한다.
- 입력: 기존 ArticleAnalysis의 주장/근거 언급/출처/주의 이유/검색 상태/단계별 오류. API 및 Pydantic/TS 계약은 유지한다.
- 동작: sourceNotice()로 실제 주의 이유와 핵심 정보 부족을 구분한다. 주의가 있으면 노랑, 주의가 없고 조사 미완료면 회색, 핵심 주장-기사 인용-원본 출처 원문 연결이 모두 완료되면 초록이다. 원문은 content_status=retrieved가 필요하다. 원본 확인만으로 기사 사실성을 입증하지 않는다.
- 출력: 출처 확인·주의 상태, 주의 목록 최대 3개·주장/출처/비교 보도 참조, 핵심 미완료 안내, 기존 상세 카드 이동. 점수·퍼센트·신뢰 등급은 없다. 아래 교차검증 재확인 기준에 해당하는 경우에만 빨간색이 우선한다.
- 예외: 분석 중/오류 화면에서는 판정 카드를 만들지 않는다. 검색 실패는 성공한 빈 검색과 구분한다. 부가 프로필 미확인이나 관련 보도 비교 실패만으로 핵심 출처를 미확인 처리하지 않는다. 기사/자료의 오래됨만으로 불이익을 주지 않는다.
- 완료 기준: 패널/배지 동일 결과, 오류·미확인에서 초록 오표시 방지, 경고+미완료 공존, 중복 이유 참조 보존, 기존 카드/팝업/근거 이동 보존. 실제 기사 품질 검증은 별도로 수행한다.

## 일반 HTTP(S) 선택·단어 요구사항 (2026-11-14)
- 목적: 사이트별 추가 등록 없이 선택한 문장과 단어를 이해한다. 입력은 접근 허용된 페이지의 DOM 선택 글과 실제 주변 문맥이다. 선택만으로 서버 요청하지 않고 확인 버튼 후 전송한다.
- 문장 동작: 본문 포함이면 기존 기사 분석을 재사용하고, 없으면 context_scope=page_excerpt로 별도 선택 분석한다. 발췌 분석은 body_truncated를 서버에서도 강제하고 전체 기사 캐시 인덱스를 덮어쓰지 않는다.
- 단어 동작: 공백 없는 단어 하나는 사전 검색과 Gemini 설명을 별도 API로 처리한다. 실제 검색 사전 도메인/ID/인용, 선택 단어의 문맥 인용을 검사한다. 사전 검색 실패·미발견·요약만 확보·원문 확보를 구분하고 불충분한 경우 AI 일반 설명으로 명시한다.
- 출력/완료: 선택 원문이 즉시 보이고 결과·오류에도 남는다. 문장/단어 분기와 문맥 범위, 사전 출처 상태가 정확하며 기존 Hover·드래그 고정·6개 카드·신뢰 점수 제거가 유지되어야 한다.
- 예외: Chrome 제한 페이지/DOM 텍스트 없는 뷰어/입력·편집 영역은 지원 범위 밖이다. 사전 의미 및 문맥의 실제 모델 품질은 별도 검증한다. 사이트가 제공하지 않는 본문이나 유료 영역을 우회하지 않는다.

## 교차검증 재확인 경고 (2026-11-14, 최신 사용자 지시)
- 목적: 다른 보도와 핵심 서술이 충돌하거나 인용 표현에 차이가 있는 부분을 원문으로 대조하게 돕는다.
- 입력/동작: 기존 비교 호출에 review_kind(none/claim_conflict/citation_difference), context_anchor를 추가한다. 서버는 보도 ID·양쪽 정확한 인용·공통 표현을 대조하고 review_status를 결정한다. 원자료 관계는 기사 실제 링크 또는 확인된 기사 인용 출처 URL로 검증한다.
- 출력: 본문 발췌+공통 표현이 확인된 후보는 빨강 교차검증 필요, 요약/제목만 또는 맥락 미확인은 노랑 후보로 표시한다. 표현상 충돌 가능성 및 왜곡 여부 확인 필요라는 문구를 쓰고 왜곡/거짓을 확정하지 않는다.
- 예외: 일반적인 강조점/관점/보도 범위 차이, 다른 시간/단위/대상을 자동 충돌로 만들지 않는다. 허위 ID·인용은 제거한다. 원문 인용 관계가 없으면 citation_difference를 승격하지 않는다.
- 완료 기준: 패널·배지·주의 카드 일치, 관련 보도 링크·대조 인용, 정확한 관련 기사로 이동, 기존 6개 토글/선택 기능 보존. 점수는 생성하지 않는다.
